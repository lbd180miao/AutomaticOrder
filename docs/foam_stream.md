# 2D 泡棉连续倒伏检测

工作台：`http://127.0.0.1:8082/vision/foam-inspector/`。

## 当前行为

- 导入 AVI / MP4 / MOV / MKV 后，后端 OpenCV 逐帧解码，算法实时计算，页面显示同一帧标注和结果。
- 支持暂停、逐帧、速度选择、进度跳转、从头检测；跳转会清除多帧历史，重新确认。
- 可直接选择 `2d_SDK/pic2` 的三个测试素材。导入文件只保存在调试目录；关闭会话后删除该临时副本，原始素材不会修改。
- 左右分别判断正常、倒伏、未确认；至少三帧且持续 0.3 秒才确认。任何一侧倒伏输出 NG，后续确认结果直接覆盖显示；连续相机的每次 NG 持久保存日志。
- 定位失败、画面不完整、黑屏等不输出 OK。历史 NG 不影响当前帧状态。
- **泡棉检测不回写 PLC，不写 DB2.DBX96.2，不修改 Z1/Z2 补偿地址。** 当前点表 DB2.DBD96 占用 96～99 字节，保持原状。
- 原单图示教入口保留在 `?legacy=1`；其配方不自动转成新的连续视频模板。

## 算法及模板范围

`apps/vision/algorithms/foam_stream.py` 不依赖 Django，无逐帧文件保存或数据库写入。
通过已示教的刚性料架结构 ORB 特征与 RANSAC 相似变换选择远端/近端参考视角；排除泡棉检测区参与定位。
在对齐后的正常展开区域中，组合背板露出、上部形态变化及灰度泡棉连通轮廓判断倒伏；暗影单独变化不判 NG。
这是针对提供的灰色泡棉、亮背板场景的可解释规则算法，并非通用泡棉分类模型。

正常模板：`media/vision/foam_stream_templates/pic2/profile.json` 及同目录 `far.png`、`near.png`。
模板分别来自人工观察为正常的 `1.avi` 第 0、38 帧，固定视角、定位区、左右区域均保存在 JSON 中。
导入视频不会把第一帧自动学习为正常，因此视频开头已经倒伏也能检测。
不同产品、背景、拍摄角度或倒伏方向需重新示教并验证；背板未明显露出的异常可能输出未确认。
当前没有基于独立标注测试集测量精确率、召回率，不应把素材回放结果宣称为生产准确率。

## 连续相机

服务按部署角色自动启动相机；在“海康相机连续检测”页查看实时画面。SDK 保持采集，不每帧停止/重启；独立采集线程只覆盖最新帧，检测线程不积压旧帧。
采集开启时单图拍照会被明确拒绝，避免切换 SDK 模式破坏连续流。关闭浏览器不停止服务器上的相机，关闭页面也不会退出手动调试。
新产品进入时无需手动清除 NG；最新确认结果自动更新。本版不提供自动多产品跟踪，NG 日志按会话与帧号记录，不自动关联产品条码。
目前仅完成模拟采集联调，未验证现场相机网络、曝光、触发模式和实际运动速度。

`FOAM_STREAM_PROFILE` 环境变量可指定其他已示教模板。
`FOAM_STREAM_AUTO_START` 控制服务启动时的连续检测，默认跟随部署角色：AGV 自动启动，外部电脑不自动控制 AGV 硬件。相机启动独立于 PLC 连接及触发，断流后自动尝试重连。
DB2.DBX68.4 已保留为停用位，不进入监听快照、事件队列或拍照流程；旧队列中的泡棉触发任务会被丢弃。原泡棉 PLC 联调接口返回 410。
`/devices/status/` 直接读取连续检测状态，约每 250ms 刷新，断流或状态过期时清除旧 OK 展示；不再把历史单图结果当作当前检测结果。
部署建议沿用单进程服务（多线程可用）；相机运行状态和视频解码会话为进程内状态，不支持多个 WSGI 工作进程共享。

## 手动连续调试与恢复自动

“进入手动连续调试”使用现有 PLC 跨进程互斥锁暂停软件自动工序分派；正在执行工序时返回忙碌，成功后才显示暂停。PLC 心跳及输入采样继续运行，不发送机器人/AGV 急停。暂停状态保存在现有 ownership 文件中，关闭页面或服务重启不自动解除。其他 PLC 调试入口不能同时接管。

“退出调试并恢复自动”只解除 2D 调试的暂停标记并清空本轮算法状态，不关闭相机，也不解除其他调试会话。恢复后继续处理自动流程保存的任务和输入队列。旧 start/stop API 分别兼容进入调试/恢复自动，不再停止采集。

相机预览独立于推理，最多约 10 帧/秒编码最新画面；算法始终处理最新帧。可勾选“查看算法标注帧”，查看与结果对应的检测框。处理帧率由服务器计算，非页面轮询频率。断流/超时清除当前有效结果和旧画面。相机特征文件中的单帧模式及各触发选择器会被覆盖为连续采集，保留曝光和网络参数。

## 2026-11-19 检测结果更新规则

实时结果不再锁存 NG：每次确认后的 OK/NG 覆盖上次结果，不回写 PLC。每个 NG 检测结果（含帧号、时间及左右侧详情）写入数据目录 foam_ng.sqlite3，检测页日志读取这些记录；不受两天 PLC 诊断日志清理影响。NG 写入失败会显示错误并重试，采集线程继续工作。单帧算法异常会清除失效结果并重试后续帧。
