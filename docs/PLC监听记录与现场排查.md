# PLC 监听记录与现场排查

设备状态页展开 PLC「查看详情」，按 2D、3D、MES 请求、料框码和连接分类查看最新 200 条记录，每 3 秒刷新。
从记录窗口建立起，每满 48 小时清空该窗口全部监听记录；后台扫描和页面查询均检查到期，停机期间不运行，恢复后首次检查清空。不删除生产历史、MES 业务记录、标定和配方。

自动监听仅使用 DB2 的五项输入：当前产品条码 DBB0（STRING[20]）、料框码 DBB24（STRING[20]）、3D 定位 DBX46.2、泡棉检测 DBX46.3、MES 封箱 DBX46.4。
产品条码和料框码首次非空时处理；后续与上次非空码不同才再次处理，空字符串不触发也不重置去重。NoRead 仅记录扫码失败，不提交 MES。视觉 Bool 首次为 1 可受理一次，之后响应 0→1；MES 封箱首次高电平也受理一次。持续为 1 不重复执行，已保存的电平跨重连保留；PLC 自行复位，软件不写这三个输入位。
输入采样独立于相机采集/计算，约每 0.5 秒轮询（受 PLC 通信锁和读间隔约束），记录采样到的变化，业务任务串行处理；MES HTTP 等待不阻塞视觉通道。完成反馈不再作为新触发的前置条件，原有视觉结果、补偿值与 MES 结果正常回写。
不再自动监听产品扫码 DBX22.0、料框到位 DBX46.0 或配方校验 DBX46.1。装箱完成信号使用采样时的料框码调用 MES 第三接口获取区位号，不以本地产品上传统计作为前置门槛；产品条码首次非空或变化时复用单件 MES 绑定流程，不依赖 DBX22.0。五路无工序先后门槛；单路业务错误只记设备页面报警记录，不锁工位，不创建需要解锁的报警，不阻断其他路。结果不明的 MES 写请求保留上下文，避免重复提交。


升级源码后执行 `.venv\Scripts\python.exe manage.py migrate` 并重启服务。已部署 EXE 需要重新构建并升级，旧包不会随源码变化。数据库应先备份，保留现场数据，不覆盖现场数据库。

截图 `PLC 192.168.192.10:102 ... TCP connection failed: timed out` 表明 S7 连接未成功，不能据此确定软件或网络根因。在 AGV 电脑 PowerShell 执行：

```powershell
Test-NetConnection 192.168.192.10 -Port 102 -InformationLevel Detailed
Get-NetIPConfiguration
route print
```

检查 SourceAddress / InterfaceAlias 是否选中连接 PLC 的网卡，目标 IP 是否正确，PLC 供电、交换机、子网和 TCP 102 是否可达。TCP 可达后再核对 Rack=0/Slot=1 是否匹配实际 PLC，并核查 S7 访问权限。DB2 读取权限和优化块设置属于连接成功后的读取排查。相机在线不能证明 PLC 链路正常。不要仅凭超时修改 PLC 地址或 Rack/Slot。

AGV 继续自动监听 PLC，通过 HTTP 转发 MES 到外部电脑；外部电脑保留硬件功能但不自动控制 AGV。


## 2026-11-13 五点读取

后台采样与设备健康检查均仅读取 DB2.DBB0 和 DB2.DBB24 各 22 字节（S7 STRING[20] 的两个头字节加内容）和 DB2.DBB46 的 1 字节，仅解析 46.2、46.3、46.4。S7 按字节读取 Bool 所在字节，其余位不参与监听。无整块 DB2 读取、无后台心跳访问、无启动批量输出初始化。

状态页逐项显示五个输入，空值/低电平显示“正在监听”，非空/高电平显示当前信号；连接或读取失败统一显示“离线”，诊断详情保留失败原因。料框码首次非空或变化、视觉首次高电平及后续上升沿保存记录并执行 MES/视觉业务，保留结果回写及校验。

## 2026-11-13 锁竞争与独立监听修正

截图的 `[Errno 36] Resource deadlock avoided` 是 Windows 本机文件锁等待错误。旧版健康检查每次另开 S7 连接，与后台采样争用锁；新版在监听运行时复用真实采样，过期或读取失败如实显示。Windows 锁改用短间隔非阻塞重试和明确的本地锁超时提示。

设备页第五部分为“报警记录”，点击展开、逐条展开详情，按单个查询日期筛选该日 00:00 到次日 00:00（不含）的记录，无结束日期。沿用原有 48 小时窗口清理策略。

3D 任务在请求采集前建立视觉历史，配方校验、相机异常及计算失败也保存失败原因；计算成功复用同一任务保存图像及结果，不重复生成历史任务。回写直接校验匹配、手眼标定与机器人坐标转换、所需补偿组和配方限值，不再使用旧的 `plc_publish_allowed` 开关拦截。匹配或标定失败时显示具体原因；有效结果按现有协议覆盖写入两组 XYZ（两层料架第二组清零）。

AGV 端监听与软件生命周期一致，旧配置或环境变量关闭标记不再禁用 AGV 自动监听，网页不能停止自动监听。网络故障持续重连；退出软件才结束。外部端保持手动硬件模式。


## 五项监听与换框绑定

料框码读取后调用 MES 第一接口查询类型，通过映射库写入 DB2.DBW76；此操作不依赖本地装箱配方。产品条码读取后先保存本地产品与当前料框绑定，再调用 MES 第二接口。料框码变化开启新一轮，保留之前的数据库绑定；排队产品保存采样时的料框码和轮次，MES 延迟返回不会串框。PLC 中未变化的旧产品码不因换框自动重新绑定。

三个触发信号首次读到高电平执行一次，持续高电平不重复，复位后再次上升可再次执行。条码查询、绑定的 MES 等待或业务失败不阻断视觉通道；装箱完成调用 20260803（RackCode），获取 BinCode 后先保存本地料框/轮次关联，再反馈 PLC；区位号缺失不报告成功。测试替身仅在测试代码中显式注入，应用启动使用真实设备。

区位号当前值保存在 StationCycle.bin_code，历次料框/轮次关联保存在 StationCycle.io_state.boxing_results；换框不清除历史关联。MES 请求与响应沿用 MesRecord 保存。


## 持续触发与断线（本次优化）

后台自动监听：连续 True 10 秒（没有采到 False）只受理一次；失败不会在同一高电平下不断重拍。读到 False 后再读到 True 才受理下一次。3D、2D、装箱完成三路一致，软件不复位三个输入位。采样线程在相机计算期间继续读取，已采到的变化先入业务队列；后续断线不会丢弃已有采样。断线期间完全发生的脉冲无法推断或补造。

自动 3D 调用当前默认配方对应采集入口，不需要手动点拍照。原始预览先关联历史，再计算；失败原因显示在历史列表和详情。持续高电平失败后，排除原因并由 PLC 复位、重新触发。


## 真实相机连续调试开关

PLC 监听记录标题右侧“调试监听”默认暗色关闭。点击开启后亮色显示；仅 2D/3D 相机通道在真实 PLC 为 True 时，完成本次采集计算后继续下一次。两路串行执行，条码/MES 仍按正常规则，避免重复绑定/封箱。再次点击关闭，正在执行的一次完成后不再连续调用；正常模式仍需新的上升沿。程序重启或监听重新启动默认关闭。此开关不启用模拟设备，也不制造 PLC 信号。

3D 任务历史左侧显示本次相机同步采集的 2D 原图，右侧保存采集当时配方 ROI 标注的 2D 图。计算失败仍保留采集画面；没有保存 2D 图的旧记录无法凭深度预览还原原始图，显示缺图说明。


## 2D/3D 仅结果覆盖写入（源码更新，未打包）

3D 仅覆盖 DB2.DBD50/54/58/62/66/70 六个 REAL：三层料架写两组有效机器人 XYZ 补偿；两层料架只用 A 组，第二组强制写零。模板匹配、标定转换或计算失败（含三层缺组、非有限值或越限）时六个值全部覆盖为零，不再写 999。保留真实错误和历史记录，零值本身不代表计算成功。

2D 仅覆盖 DB2.DBX74.1：OK=True，NG 或检测异常=False。两路不再清写完成位/成功位，不修改 PLC 触发输入，也不等待完成位复位。正常上升沿触发、按钮启用的高电平连续调试保持不变。通信中断时无法保证写入，错误记录在日志中。
