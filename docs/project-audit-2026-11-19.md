# 项目检查与修复记录（2026-11-19）

## 已确认的业务规则

- 3D 由 PLC 上升沿触发拍照、定位计算，页面自动更新本次结果。
- 2D 持续采集和检测，最新 OK/NG 覆盖显示，未确认不显示 OK；不回写 PLC。
- 连续相机每个确认 NG 的检测结果均需持久记录，不因后续 OK 删除。
- 同槽位再次使用同一料框前会出现另一有效料框码，保持现有有效码去重规则。

## 已修复

1. 2D NG 永久锁存：改为当前多帧确认结果；历史首次 NG 信息仍保留。
2. 2D 没有持久 NG 日志：增加数据目录 `foam_ng.sqlite3`，每条记录含会话/代次/帧唯一键、记录时间、完整算法结果。检测页日志读取最近记录。此数据库不参与两天 PLC 诊断日志清理。日志写入失败提示并重试，采集继续；NG 记录成功后才发布结果。正常关闭/重启保留已提交记录。
3. 单帧算法异常终止相机：异常只清除当前检测结果，重新建立多帧证据并处理后续帧，预览继续。
4. 3D 失败仍显示上次 OK：按最新生产任务选择页面结果；在请求相机前创建任务，采集失败也保存失败状态。没有本次结果时不回退上一条成功记录。
5. 打包遗漏 2D 标准图：标准模板移交打包资源白名单复制，并写入资源清单；仅三个固定模板文件，不复制整个 media 或 SDK。补充关闭 SQLite 连接，避免 Windows 打包文件占用。

## 尚需处理

### 旧测试与当前协议不一致

明确存在旧测试要求 position_done 等已移除反馈、foam_trigger 进入快照、四输入协议、旧泡棉配方接口或旧点云算法。这些需要按现行协议重写，不能通过恢复退役功能来消除失败。其余失败还包括测试替身/数据库权限设置问题，尚未逐条完成归因。全量套件不是可用的发布门禁。

### 模型与迁移不一致

`makemigrations --check --dry-run` 检出：

- RackRecipe 模型缺少迁移 0006 已建立的 rack_location_recipe 字段，自动生成会删除旧配方关联列。
- WorkflowInstance.current_state choices 与迁移状态不一致。

未生成或执行删除字段迁移，原配方、标定数据保留。后续应确定是否保留该历史字段于模型中，或采用只调整迁移状态且保留数据列的兼容方案，并补齐 choices 迁移。

### 运维边界

- NG 逐帧保存、无自动清理，需按实际 NG 频率制定归档保留策略；当前页面仅显示当天最近日志，数据库仍保留历史记录。
- NG 日志记录检测帧结果，不保存每帧图像、不自动关联产品条码。
- 若启动时模板本身无效，仍需修复模板后重新启动检测；此次异常恢复针对运行中的单帧算法错误。
- 仅单进程拥有相机运行状态；多 WSGI 进程共享相机不在本次验证范围。
