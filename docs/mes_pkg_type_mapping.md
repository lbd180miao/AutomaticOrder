# MES 包装编码与料架类型

执行 `python manage.py migrate` 后，在 `/admin/mes/pkgtypemapping/` 维护「MES 包装编码映射」。每个 PkgTypeCode 唯一，多个编码可以对应同一种类型；类型只允许「两层 / 三层 / 五层」，可禁用单条配置，修改后下次校验立即生效。

迁移预置 31231321～31231328 → 三层、8888812312～8888812319 → 两层。五层实际编码需现场维护，不根据编码规律推测。编码以字符串保存，保留前导零。

20260801 的 PkgTypeCode 经配置表转换为 rack_type，原始 MES 响应及转换结果保存在 MES 通讯记录。缺失、空值、未配置或禁用的编码导致校验失败，禁止继续装箱。失败记录补传时也重新查表。

本地装箱配方的料架类型须使用相同中文标准值，层数分别为 2、3、5。优先使用已绑定且类型、层数一致的启用配方，否则只选择同类型、同层数唯一的启用配方。不会沿用其他类型的旧绑定，也不会回退到全局唯一配方。无匹配或存在多个候选时需维护并绑定配方。旧 REST/模拟响应不含包装编码字段时保留原有逻辑。

20260802 仍发送 RackCode + Barcode；20260803 仍发送 RackCode 并读取 BinCode，不把包装编码或中文类型写入这两个接口。

此功能支持五层编码分类和配方匹配；当前 3D 配方就绪校验仍仅支持第 1～3 层，五层自动定位能力需独立验证和扩展。测试使用模拟 MES 响应，不代表已完成现场网络联调。
